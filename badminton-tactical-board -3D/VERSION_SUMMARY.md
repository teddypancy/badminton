## 三、系統架構與資料流（交接必讀）

### 3.1 分層架構

```text
BTB.html（入口，importmap 載入 Three.js 0.147.0）
   └─ js/main.js（應用入口：綁定事件、暴露 window.* 全局函數給 HTML 呼叫）
        ├─ config/constants.js ── 常數定義（改參數先看這裡）
        ├─ core/state.js ──────── 全局狀態（唯一事實來源，所有模組共用）
        ├─ core/physics.js ────── 物理唯一權威（軌跡、攔截點、診斷；渲染層禁止自行算軌跡）
        ├─ core/trajectory.js ─── 軌跡採樣（physics 的包裝服務）
        ├─ models/shot.js ─────── 拍次業務邏輯（智能配速、攔截點、級聯更新）
        ├─ models/player.js ───── 球員模型與站位
        ├─ 2d/ ─────────────────  Canvas 平面戰術板（渲染、交互、側視圖、彈窗）
        ├─ 3d/ ─────────────────  Three.js 立體場景（場景、實體、動畫、視角）
        ├─ ui/ ─────────────────  面板（參數、日誌、腳本庫）
        └─ utils/ ─────────────── 通用工具
```

### 3.2 核心資料流（改一拍之後發生什麼事）

```text
使用者操作（點擊落點 / 拖拽端點 / 改參數）
  → shot.js 智能匹配鏈：
      matchReceiverSpeed（接球方速度，依下一拍 hitLevel）
      → computeHitPoint（攔截點，帶位忠實 + 防守半場檢查）
      → applySmartPositions（站位吸附）
  → cascadeBallPositions（級聯：後續拍起点 = 前拍攔截點或落點）
  → 同步渲染四件套：
      render2D（2D 戰術板）+ sync3DPositions（3D 場景）
      + renderSideProfile（側視圖）+ updateParamPanel / updateLog（面板）
```

### 3.3 動畫播放流

```text
startAnimation → animTime 依 playSpeed 推進
  → 每帧位置由 physics.js getTrajectoryPoint 提供（唯一計算來源）
  → 球到達 hitPoint.t（攔截時刻）即切下一拍，觸發橙色脈衝（v0.3 B1）
  → 攔截點為 null 時播到球落地
```

### 3.4 v0.3 三大關鍵機制（改動前必懂）

| 機制 | 內容 | 主要落點 |
|------|------|---------|
| 帶位忠實選點（方案 D） | 高位宣告 → 攔截點限 2.0–3.0m；中位 → 1.4–2.0m；壓制球低位 → 0.1–3.0m | physics.js findInterception（maxBallY 參數） |
| 降級配速（effLevel） | 高位追不到 → 改用中位標準配速 → 再追不到改走路標準；使用者的宣告（高/中/低）不變 | shot.js matchReceiverSpeed |
| 切拍時機 | 3D 動畫在攔截時刻切拍（不播到落地）；2D 接球方永遠吸附落點 | animation.js / renderer.js |

## 四、核心業務概念詞彙表（交接必讀）

| 術語 | 意義 |
|------|------|
| 拍次（shot） | 一次球的飛行，從擊球點到落點/攔截點；全部存在 `state.shots` 陣列 |
| 設定拍（index 0） | 發球設定拍，不參與飛行動畫、不可刪除；改發球方會觸發 updateShot1Server |
| ballFrom / ballTo | 球的起點與終點 `{x,y,z}`；ballFrom.y 為擊球高度（發球固定 1.15m） |
| 球路（arcType） | `high_arc` 高球 / `mid_high_arc` 平高球 / `low_flat_arc` 平球 / `fast_press` 快壓 / `soft_press` 輕壓；後兩者 `isPress: true`（壓制球） |
| 擊球高度宣告（hitLevel） | `'high' / 'mid' / 'low'`，由**下一拍**宣告，決定**本拍**接球方速度與攔截帶位 |
| 攔截點（hitPoint） | `{x,y,z,t}`，t 為攔截時刻佔全程比例；`null` 代表球落地無人攔截 |
| 帶位 | 高位 2.0–3.0m／中位 1.4–2.0m／低位（限壓制球）0.1–3.0m；另有限制顯示用的常數 0.8–2.8m |
| 智能匹配 | 順序固定：速度 → 攔截點 → 站位；手動攔截點覆寫優先於智能匹配 |
| 降級配速（effLevel） | 高不可達降中位、中不可達降走路；降級時保留原宣告並顯示診斷訊息 |
| 級聯更新 | 前拍變動時，後續拍起點 = 前拍攔截點（若有）否則落點 |
| previewPositions | 攻防雙方預覽站位；同時是速度診斷的起點 |
| appMode | `'smart'` 腳本模式 / `'free'` 手繪模式 |
| mode | 腳本類型：`'singles' / 'doubles' / '2v1' / '3v1'` |

## 十二、開發與測試指南（含已知陷阱）

### 12.1 如何運行

| 操作 | 命令 |
|------|------|
| 啟動本地伺服器 | `python -m http.server 8932`（在專案根目錄執行） |
| 開啟頁面 | 瀏覽器打開 `http://localhost:8932/BTB.html` |
| 除錯 | F12 → Console 檢查錯誤與初始化訊息 |

- **必須用靜態伺服器**，不能用 file:// 直接雙擊打開（ES Modules + importmap 在 file:// 下無法運作）
- Three.js 從 CDN 載入，首次開啟需網路

### 12.2 已知陷阱（鐵律，違反會誤判或弄壞東西）

| # | 陷阱 | 正確做法 |
|---|------|---------|
| 1 | 跨場景測試污染：A 場景的殘留狀態（如 ballFrom.y=2.3）污染 B 場景，造成誤判 | 每個測試場景前必須乾淨重載頁面或明確重置狀態 |
| 2 | ES Module 磁碟快取：改了 js 檔但瀏覽器仍跑舊碼 | Ctrl+F5 強制重載；程式化驗證用 `fetch(url, {cache:'reload'})` |
| 3 | 速度 toFixed 舍入：接球方速度捨入後可能比攔截時刻慢一點點 | 配速已內建 5% 餘量（分母 ×0.95），改配速邏輯時不可移除 |
| 4 | 在渲染層自行算軌跡 | 一切軌跡計算必須走 physics.js 的 getTrajectoryPoint() |
| 5 | CSS 載入順序 | responsive.css 必須最後載入；改 CSS 後核對 main.css 的 @import 順序 |
| 6 | localStorage key 版本字樣 | 維持 v0.2 字樣，升版本不換 key（保護使用者腳本庫） |
